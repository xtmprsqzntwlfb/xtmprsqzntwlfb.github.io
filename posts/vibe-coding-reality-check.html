Vibe Coding Reality Check

July 14, 2026

I spent some time running an experiment on real OpenStack Horizon work: could an AI coding assistant produce valid, reviewable code if I gave it a clear description of the task and pointed it at existing reviewed code as an example, without me directing every individual change?

It couldn't.

The Setup

The task seemed ideal for this kind of test: migrating several API modules from a legacy client library to a newer one — repetitive work with a clear pattern and a reference implementation that had already passed code review.

In the simplest cases it worked on the first try, but the problems appeared the moment anything deviated from the happy path. The first migration required a backward-compatibility layer because of some specific complications, and the assistant learned this as the pattern, applying it to every subsequent module, even when a clean break was simpler and better. The compatibility layer was a judgment call for one specific situation, not a template, but the assistant couldn't tell the difference. Each time I had to stop it and give explicit instructions on what to do instead.

The Argument

The most revealing moment came when the tests started failing after the assistant's changes, and it insisted the failures were unrelated to its work. It analyzed the errors, looked at the test code, and concluded this must be a pre-existing issue. I disagreed: the test was passing before the change, it failed after, and that's not a coincidence, but the assistant held firm:

"Try changing these lines and you'll see the tests are still failing."

So I did. And the tests passed.

"OK, you were right."

The assistant can reason about code it sees, but it can't draw on years of context it was never part of.

The Spiral

When the assistant got stuck on another failing test, it tended to escalate rather than reconsider: proposing increasingly invasive fixes, restructuring working code, adding helper functions to work around a problem it hadn't correctly diagnosed. After three rounds of this on one migration, I traced the actual error myself and found it in a completely different file. The tests were correct all along: the assistant had been "fixing" the wrong thing across three iterations, each one making the codebase worse. A human developer recognizes the feeling of going in circles and changes strategy; the assistant just keeps swinging harder.

The Conclusion

The irony of AI coding assistants is that they're most useful to people who need them least. To get valid code out of the assistant, I had to specify exact files and functions, override its architectural decisions and catch cross-module side effects it couldn't see, which meant I had to understand the code at least as well as if I were writing it myself. The time I spent rolling back bad fixes and describing context exceeded the time it would have taken to write the migration by hand.

Vibe coding works well enough for prototypes and pet projects, and AI assistants are genuinely good at generating boilerplate and following established patterns for well-scoped tasks, but the idea that you can simply describe what you want and get working production code falls apart on any project with real complexity and cross-module dependencies that require human judgment to navigate. There's no shortcut past understanding: the AI can type faster than you, but it can't think for you. Not yet.
